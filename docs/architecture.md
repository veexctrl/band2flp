# Architecture

The intended pipeline keeps GarageBand parsing separate from FL Studio writing:

```text
.band package -> package/parser -> neutral Project -> JSON/debug output
                                             `-> FLP arrangement exporter
                                                     + linked audio sources
```

`band2flp.parser` performs bounded, read-only ZIP, plist, chunk-boundary, and event-record parsing. `band2flp.model` defines the format-neutral project, track, region, and media-reference types. Summary tempo/meter values are read from metadata; matching group-zero tempo/meter events are exposed as high-confidence candidates with raw positions and unknown units. Audio placement records populate neutral tracks and regions with candidate beat starts, external media references, and raw event data. Their Logic-derived origin and PPQ agree with one research preview, but the parser labels the conversion as a hypothesis for each input project until independently validated. Same-group `AuRg` chunks whose NUL-delimited filename stem matches an audio resource are reported separately as stronger source-to-region-chunk links. `band2flp.media` provides an opt-in command that extracts only uniquely matched `AudioFiles` references using generated filenames into a new directory; inspection does not copy media. MIDI `0x20` events are cross-linked to unique `MSeq` chunk groups in inspected fixtures and exposed as placement candidates. MIDI `0x90` note-shaped records are exposed as unconfirmed field candidates; in one fixture they share an `MSeq` chunk with a placement candidate. A separate research probe found that the arrange model's saved `previousCurrentTrackUUID` matches bytes at `Trak` payload offset `+0x18` in both supplied fixtures; this is a cross-component candidate link, not yet a complete arrange-track mapping. MIDI placement track bytes and timing remain untransferred to the neutral model. Region durations, audio placement-event-to-region-object ordinals, track names, and other track settings remain unknown. The `project_data` field carries chunk/event records, archive-level observations, and complete retained payload bytes.

Timing fields on future notes and regions are represented as exact beat strings. Their units and mapping will be set only after differential evidence identifies the source encoding. The parser exposes the raw numeric duration summary with an unknown unit; it does not convert that value into beats or seconds.

`band2flp.flp_export` consumes the neutral `Project` and serializes experimental audio arrangements through optional PyFLP using a user-provided empty FLP template. It creates sampler channels and playlist clips, carries summary tempo and meter when present, and writes a JSON sidecar. Unknown region durations are rejected by default. The explicit `source-full` policy uses complete source-file lengths as placeholders and warns that trim, loop, source-offset, and playback-stretch behavior are not recovered. MIDI, automation, section structure, track names, and mixer properties are not yet exported. PyFLP save/reparse has been verified locally; FL Studio 25 GUI load and playback remain unverified.
