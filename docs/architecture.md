# Architecture

The intended pipeline keeps GarageBand parsing separate from FL Studio writing:

```text
.band package -> package/parser -> neutral Project -> JSON/debug output
                                             `-> FLP arrangement exporter
                                                     + linked audio sources
```

`band2flp.parser` performs bounded, read-only ZIP, plist, chunk-boundary, and event-record parsing. `band2flp.model` defines the format-neutral project, track, region, and media-reference types. Summary tempo/meter values are read from metadata; matching group-zero tempo/meter events are exposed as high-confidence candidates with raw positions and unknown units. Audio placement records populate tracks and regions with candidate beat starts, external media references, and raw event data. The parser currently groups audio placements using the `+0x14` byte minus one as `Track.index`, while retaining the original byte as an explicitly unconfirmed candidate; relative row order has HIGH CONFIDENCE in one preview fixture, but absolute index semantics remain a HYPOTHESIS. The start conversion uses a Logic-derived origin and PPQ and agrees with one research preview, but remains a hypothesis for each input project. Same-group `AuRg` chunks whose NUL-delimited filename stem matches an audio resource are reported separately as stronger source-to-region-chunk links. ARR-036 also found four one-to-one `AuRg` / placement field matches in one source group using an eight-byte candidate field; a uniquely anchored zero slot was needed, and the field's meaning and stability under reorder remain hypotheses. `band2flp.media` provides an opt-in command that extracts only uniquely matched `AudioFiles` references using generated filenames into a new directory; inspection does not copy media. MIDI `0x20` events are cross-linked to unique `MSeq` chunk groups in inspected fixtures and exposed as placement candidates. MIDI `0x90` note-shaped records are exposed as unconfirmed field candidates; in one fixture they share an `MSeq` chunk with a placement candidate. A separate research probe found that the arrange model's saved `previousCurrentTrackUUID` matches bytes at `Trak` payload offset `+0x18` in both supplied fixtures; this is a cross-component candidate link, not yet a complete arrange-track mapping. MIDI placement track bytes and timing remain untransferred to the neutral model. Region durations, track names, and other track settings remain unknown. The `project_data` field carries chunk/event records, archive-level observations, and complete retained payload bytes.

Timing fields on future notes and regions are represented as exact beat strings. Their units and mapping will be set only after differential evidence identifies the source encoding. The parser exposes the raw numeric duration summary with an unknown unit; it does not convert that value into beats or seconds.

`band2flp.flp_export` consumes the neutral `Project` and serializes experimental audio arrangements through optional PyFLP using a user-provided empty FLP template. It creates sampler channels and playlist clips, carries summary tempo and meter when present, and writes a JSON sidecar. Unknown region durations are rejected by default. The explicit `source-full` policy uses complete source-file lengths as placeholders and warns that trim, loop, source-offset, and playback-stretch behavior are not recovered. The optional `--include-midi-candidates` path creates editable MIDI preview patterns from unconfirmed GarageBand note candidates. It uses a uniquely linked printable `MSeq` text candidate as a provisional display label, while leaving the label's role and GarageBand track identity unconfirmed. It does not yet assign GarageBand tracks, pitches, velocities, onsets, or durations with confirmed semantics. FL Studio 25 accepted synthetic audio arrangements and a WAV-relinked local probe, and a one-field synthetic note-flag probe changed ghost notes into editable notes. These GUI checks validate those specific FLP structures in the tested version, not full GarageBand reconstruction or audible playback. Automation, section structure, track names, and mixer properties are not exported from the GarageBand track model.

The `export-flp --midi-only` CLI mode removes audio regions before export, enables provisional MIDI previews, skips media extraction, and rejects conflicting audio-export options. It creates review FLPs without audio channels or sample references.
